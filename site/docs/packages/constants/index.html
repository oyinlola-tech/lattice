@zudojs/constants

v0.0.1 — Shared Constants, Enums & Type-Safe Literals

The foundational package for the entire Zudo ecosystem. Provides branded types, HTTP constants, lifecycle states, validation patterns, cache strategies, serialization limits, time utilities, and runtime abstractions. Every @zudojs/* package depends on this.

LEAF PACKAGE NO DEPENDENCIES (except @zudojs/errors) Node.js ≥ 24

Overview

@zudojs/constants is the lowest-level package in the Zudo framework. It defines the shared vocabulary — types, enums, limits, patterns, and sentinel values — that every other package references. You never import these from individual packages; you always import from @zudojs/constants.

Rule: Never redefine a type that already exists in @zudojs/constants. Import it instead. See the Type Ownership Table in AGENTS.md.

Branded Types

Branded types prevent mixing unrelated string/number values at compile time. A UserId is structurally a string, but TypeScript won't let you pass a plain string where a UserId is expected.

The Brand Utility

// src/common/common.type.ts export type Brand<T, B> = T & { readonly __brand: B };

Factory Functions

Create branded values from raw strings. These cast the value at runtime — no validation is performed.

import { createUserId, createEventId, createRequestId, createCorrelationId, createTimestamp } from "@zudojs/constants"; const userId = createUserId("usr_abc123"); // UserId const eventId = createEventId("evt_xyz789"); // EventId const reqId = createRequestId("req_001"); // RequestId const corrId = createCorrelationId("corr_001");// CorrelationId const ts = createTimestamp("2026-01-15T10:30:00.000Z"); // Timestamp // These now prevent accidental mixing: function getUser(id: UserId): User { /* ... */ } getUser(userId); // ✅ compiles getUser(eventId); // ❌ Type error — EventId is not UserId getUser("usr_abc"); // ❌ Type error — string is not UserId

Valid Transitions

The state machine enforces legal transitions:

import { LIFECYCLE_VALID_TRANSITIONS } from "@zudojs/constants"; // idle → initializing, failed // initializing → initialized, failed // initialized → starting, failed, disposed // starting → started, failed, disposed // started → ready, stopping, failed // ready → stopping, failed // stopping → stopped, failed // stopped → disposed // failed → disposed // disposed → (terminal state) const nextStates = LIFECYCLE_VALID_TRANSITIONS[LifecycleState.IDLE]; // → [LifecycleState.INITIALIZING, LifecycleState.FAILED]

Errors

Package-specific errors extending BaseError from @zudojs/errors.

import { InvalidConstantError, ConstantContextError } from "@zudojs/constants"; // Thrown when an invalid constant value is used throw new InvalidConstantError("Invalid HTTP method: CHEESE"); // Thrown when a constant is used outside its valid context throw new ConstantContextError("Lifecycle transition not allowed");
Note: These extend BaseError from @zudojs/errors, not Error directly. The base error type must always come from the errors package.

Testing

How to use constants in tests with mock utilities.

import { describe, it, expect } from "vitest"; import { createMockClock, createMockRandom, LifecycleState, LIFECYCLE_VALID_TRANSITIONS } from "@zudojs/constants"; describe("Lifecycle transitions", () => { it("should only allow valid transitions", () => { const valid = LIFECYCLE_VALID_TRANSITIONS[LifecycleState.IDLE]; expect(valid).toContain(LifecycleState.INITIALIZING); expect(valid).toContain(LifecycleState.FAILED); expect(valid).not.toContain(LifecycleState.READY); }); }); describe("Time conversion", () => { it("should convert seconds to milliseconds", () => { expect(toMilliseconds(5, "seconds")).toBe(5000); }); }); describe("Mock clock", () => { it("should return fixed time", () => { const clock = createMockClock(1000); expect(clock.now()).toBe(1000); expect(clock.now()).toBe(1000); // doesn't advance }); });
