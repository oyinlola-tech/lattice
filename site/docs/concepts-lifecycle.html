Lifecycle

State machine for component lifecycle management with hooks and dependency ordering.

LIFECYCLE STATE MACHINE HOOKS

Overview

@zudojs/lifecycle provides a state machine for managing component lifecycle. Every component transitions through well-defined states with hooks that execute at each transition.

Architecture Position

Sits in Layer 2 (Runtime Primitives). Used by @zudojs/runtime, @zudojs/adapters, and @zudojs/storage.

Lifecycle States & Transitions

Components transition through these states in order. Invalid transitions throw errors.

Created
Initial state
→
Initialized
onInit hook ran
→
Started
onStart hook ran
→
Stopped
onStop hook ran
→
Disposed
onDispose hook ran

State Hooks

Each lifecycle transition triggers a hook. Implement these hooks to define component behavior.

import { LifecycleComponent } from "@zudojs/lifecycle"; class DatabaseService implements LifecycleComponent { readonly name = "database"; readonly dependencies = []; // No dependencies async onInit(): Promise<void> { // Validate config, check connectivity await this.validateConnection(); } async onStart(): Promise<void> { // Open connection pool this.pool = await createPool(this.config); } async onStop(): Promise<void> { // Drain connection pool await this.pool.drain(); } async onDispose(): Promise<void> { // Release all resources await this.pool.destroy(); } }

Dependency Ordering

The lifecycle manager topologically sorts components by their declared dependencies. Components start in dependency order and stop in reverse order.

class ApiServer implements LifecycleComponent { readonly name = "api-server"; readonly dependencies = ["database", "cache"]; // Starts AFTER database and cache } class CacheService implements LifecycleComponent { readonly name = "cache"; readonly dependencies = ["database"]; // Starts AFTER database } // Start order: database → cache → api-server // Stop order: api-server → cache → database

Graceful Shutdown

The lifecycle manager handles SIGTERM/SIGINT signals and orchestrates a graceful shutdown sequence. In-flight requests complete before components stop.

Production Note

Always implement onStop and onDispose hooks. Missing cleanup leads to orphaned connections, memory leaks, and zombie processes.

Why Lifecycle Matters

  • 01 Predictable startup — components initialize in the correct order, every time.
  • 02 Clean shutdown — no orphaned resources, no data corruption on process exit.
  • 03 Error recovery — if a component fails to start, dependent components are skipped.
  • 04 Testability — start and stop individual components in isolation.
